## 1. Products / APIs

### Overview
- https://docs.parallel.ai/llms.txt: "Parallel's web APIs (Search, Extract, Task/Deep Research, Responses, FindAll, and Monitor) give AI agents and developers high-quality, low-latency access to the web". The docs also cover Decisions, Images, Places, Shopping, Flights, Hotels, and Entity Search.
- Timing per API, from https://docs.parallel.ai/getting-started/pricing.md (summary table):
  - Search: "200 ms–3 s Synchronous"
  - Extract: "1–20 s Synchronous"
  - Task: "10 s–2 hr Asynchronous"
  - Responses: "5–60 s Synchronous"
  - Monitor: "Ongoing Asynchronous"
  - FindAll: "10 s–2 hr Asynchronous"
  - Entity Search: "1–3 s Synchronous"

### Task API (async deep research and enrichment)
- **Async and stateful.** https://docs.parallel.ai/task-api/guides/execute-task-run.md: "Task runs are stateful objects, which means that creating a Task Run and retrieving its results are separate calls to the API." States: `queued`, `running`, `completed`, `failed`.
- **Endpoints**
  - `POST https://api.parallel.ai/v1/tasks/runs` (https://docs.parallel.ai/task-api/webhooks.md).
  - `GET /v1/tasks/runs/{run_id}/result`, which "Retrieves a run result by run_id, blocking until the run is completed." Query param `timeout` defaults to `600`. A `408` means "Request timed out; run still active" (https://docs.parallel.ai/api-reference/tasks/retrieve-task-run-result.md).
- **Result delivery.** Three options:
  - Blocking or polling GET.
  - Webhook (`task_run.status`).
  - SSE. You set `"enable_events": true` and then `GET /v1/tasks/runs/{id}/events`, which emits events such as `task_run.state` and `task_run.progress_msg.*` (https://docs.parallel.ai/task-api/task-sse.md).
- **Batch (Task Groups).** `POST /v1/tasks/groups/{taskgroup_id}/runs` is "Up to 1,000 runs per POST request". The runs endpoint "streams back the requested runs immediately using SSE" (https://docs.parallel.ai/task-api/group-api.md).
- **Processors and latency** (https://docs.parallel.ai/task-api/guides/choose-a-processor.md):
  - lite: 10s–2min, ~2 fields
  - base: 15s–3min, ~5 fields
  - core: 60s–5min, ~10 fields
  - core2x: 60s–10min, ~10 fields
  - pro: 2min–10min, ~20 fields
  - ultra: 3min–25min, ~20 fields
  - ultra2x: 5min–50min, ~25 fields
  - ultra4x: 5min–90min, ~25 fields
  - ultra8x: 5min–2hr, ~25 fields
  - Observed p50/p90, for example: "`lite` | 45s | 1.5min", "`core` | 1.5min | 3min", "`ultra` | 4min | 10min". Queue time "**is not included**".
  - The pricing page lists slightly different latency ranges, for example lite "10s - 60s" and base "15s - 100s".
- **Input and output schemas** (https://docs.parallel.ai/task-api/guides/specify-a-task.md):
  - `output_schema` is required and `input_schema` is optional. Formats are "JSON Schema or Text". Schema types are `json`, `text`, and `auto`. "`auto` mode enables Deep Research style outputs only in processors `pro` and above."
  - Schema rules: "Root type must be object". "All fields must be required" (warning). Optional fields use `["string","null"]`.
  - Limits: "Nesting depth | error | 5 levels", "Total properties | error | 100". The "combined length of your task specification AND input data cannot exceed 25,000 characters."
- **Citations, basis and confidence** (https://docs.parallel.ai/task-api/guides/access-research-basis.md):
  - Output has `content`, `basis`, and `type` (`json`/`text`).
  - FieldBasis = `field`, `citations` (`url`, `excerpts`), `reasoning`, `confidence`.
  - "All processors include a confidence rating for each output field". Levels are High, Medium, and Low.
  - Per-element basis uses paths like `key_executives.0`.
  - "As of August 24, 2026, omit the legacy `parallel-beta: field-basis-2025-11-25` header".
- **Limit discrepancy.** The Task lifecycle page says "**2,000 requests per minute** per API key. This limit applies across all POST and GET requests" (https://docs.parallel.ai/task-api/guides/execute-task-run.md). The rate-limits page says GET requests "do not count against these limits" (https://docs.parallel.ai/getting-started/rate-limits.md).

### FindAll API (async entity-list building, public beta)
- https://docs.parallel.ai/findall-api/findall-quickstart.md:
  - "**Beta Notice**: Parallel FindAll is currently in public beta… We will provide 30 days notice before any breaking changes."
  - It "turns natural language queries into structured, enriched databases of companies, people, and other real-world entities".
  - "Evaluated fields can include reasoning and source citations through `basis`".
  - "Asynchronous Processing".
- **Endpoints.** `POST /v1beta/findall/runs`. Entity Search is at `/v1beta/findall/entity-search` (https://docs.parallel.ai/getting-started/rate-limits.md).
- **Lifecycle.** "`queued` → `running` → a terminal state (`completed`, `failed`, or `cancelled`)". Termination reasons include `match_limit_met`, `low_match_rate`, `candidates_exhausted`, `timeout`, and `insufficient_funds` (https://docs.parallel.ai/findall-api/core-concepts/findall-lifecycle.md).
- **Delivery.** SSE and webhooks. Webhook events are:
  - `findall.candidate.generated`
  - `findall.candidate.matched`
  - `findall.candidate.enriched`
  - `findall.run.completed`
  - `findall.run.cancelled`
  - `findall.run.failed`
  - Source: https://docs.parallel.ai/findall-api/features/findall-webhook.md
- **Entity Search.** This is the "fast, synchronous counterpart… without FindAll's verification, enrichment, or citations" (findall quickstart).

### Monitor API (async, scheduled web change monitoring)
- https://docs.parallel.ai/monitor-api/monitor-quickstart.md: "Define a query once and Monitor continuously watches the web for new, relevant updates… delivering it to your systems via webhook."
- **Endpoint.** `POST https://api.parallel.ai/v1/monitors` with `type` (`event_stream`/snapshot), `frequency`, `processor` (`lite` default, `base`), and `webhook`.
- **Not for history.** "Monitor tracks new updates from the time of creation."
- **Frequency.** "`frequency` (1h–30d)" (https://docs.parallel.ai/getting-started/overview.md, in llms-full) and "top-level `frequency` (`1h`–`30d`)" (https://docs.parallel.ai/monitor-api/monitor-migration-guide.md).
- **Events.** `event_type` is one of `event_stream`, `snapshot`, `completion`, or `error`. Each event output "Includes `type`, `content`, and `basis`". `event_id` is "Safe to use for client-side deduplication" (https://docs.parallel.ai/monitor-api/monitor-events.md).
- **Webhooks.** Event types are `monitor.event.detected`, `monitor.execution.completed`, and `monitor.execution.failed` (https://docs.parallel.ai/monitor-api/monitor-webhooks.md).

### Extract API (sync)
- https://docs.parallel.ai/extract/extract-quickstart.md: "converts any public URL into clean markdown, including JavaScript-heavy pages and PDFs. It returns focused excerpts aligned to your objective, or full page content if requested."
- **Endpoint.** `POST /v1/extract`. Per-request limit: "URLs to extract content from. Up to 20 URLs." (https://docs.parallel.ai/api-reference/extract/extract.md)
- **Latency.** "1–20 s Synchronous" (pricing page).

### Search API (sync)
- **Endpoint.** `POST /v1/search`. `search_queries` is required. `max_results`, `source_policy`, and `fetch_policy` go inside `advanced_settings` (https://docs.parallel.ai/getting-started/pricing.md banner).
- **Modes** (https://docs.parallel.ai/search/modes.md): turbo ~200ms, fast ~700ms, basic ~1s, advanced ~3s. "If `mode` isn't set, requests default to `advanced`."
- **Result count.** "Public Search modes currently cap results at 20" (https://docs.parallel.ai/search/advanced-search-settings.md).
- **Freshness.** "By default, Search returns excerpts from pages Parallel has already indexed" (same page). A live fetch requires a `fetch_policy`.

### Chat API / Responses API
- **Chat API is historical.** The "Chat API" appears only in the changelog: "Parallel Chat is now generally available in beta… OpenAI ChatCompletions compatible" (https://docs.parallel.ai/resources/changelog). The current docs present the **Responses API** instead.
- **Responses API** (https://docs.parallel.ai/responses-api/responses-quickstart.md):
  - "an OpenAI Responses-compatible endpoint that answers a question using live web research within a latency budget of ~5–60 seconds".
  - Model `parallel`, with `reasoning.effort` set to low, medium (default), or high.
  - `base_url="https://api.parallel.ai/v1"`.
  - Synchronous, with optional streaming.
- **Other sync APIs.** Decisions, Images, Places, Shopping, Flights, and Hotels are also synchronous (pricing page).

- **Responses:** low $10, medium $50, high $250 per 1,000. "You are only charged for successful responses."
- **Decisions / Images / Places:** $1–$5 per 1,000.
- **Shopping / Flights / Hotels:** $5 per 1,000.

### Plans and free credits (https://parallel.ai/pricing.md)
- **Launch.** Free via the MCP server, "No account needed", "Variable limits, enough for personal use".
- **Build.** "Pay-as-you-go. $5 free monthly with a card on file, plus up to $80 at signup." It includes "Up to 5,000 free requests per month" and "Auto-reload and spend limits". Billing is "Card".
- **Scale.** "$1,000/mo Or $10,000 / year charged upfront, for $12,000 in credits over 12 months". "Monthly credits don't roll over."
- **Enterprise.** Custom pricing, with "Invoicing and marketplace billing".
- **Startups.** "Qualified startups can receive up to $250 in free credits".
- **Spend order.** "Free credit is always spent before any paid balance". Prices are "before credits and tax".

### Billing model
- **Prepaid balance.** Credits are reserved per task, and an insufficient balance returns 402: "the system reserves credits for the estimated cost before processing begins" (https://docs.parallel.ai/resources/warnings-and-errors.md).
- **Card billing.** Self-serve is billed through a payment processor with optional auto-reload: "If Customer enables the auto-reload functionality…" (https://parallel.ai/customer-terms.md §6(b)).
- **Price changes.** Non-decrease price changes take effect "14 days after they are posted" (§6(a)).
- **No refunds.** "Any payment is non-cancellable and non-refundable" (§6(b)).

### Budget controls
- **Spend limits are notify-only.** https://docs.parallel.ai/resources/faqs.md: "Organization admins can set a monthly spend limit for the whole organization, or for an individual app… Limits are notify-only; they never block requests."
- **Hard stop is the balance.** The real hard stop is the prepaid balance. FindAll terminates with `insufficient_funds`, and other APIs return 402.
- **Monitoring APIs.** A Balance API and a Usage API exist (https://docs.parallel.ai/service-api/balance/get-balance.md, https://docs.parallel.ai/integrations/usage-api.md).
- **Minimum purchase.** Not found in official pages.

## 3. Authentication, base URL, rate limits
- **Header.** `x-api-key`. The OpenAPI spec defines `ApiKeyAuth: type: apiKey, in: header, name: x-api-key` (https://docs.parallel.ai/api-reference/tasks/retrieve-task-run-result.md).
- **Base URL.** `https://api.parallel.ai` (same OpenAPI spec, `servers`).
- **EU base URL.** `https://eu.parallel.ai` serves Search and Extract only and requires an enterprise agreement. "The `x-api-key` header stays the same." (https://docs.parallel.ai/resources/eu-data-residency.md)
- **Rate limits** (https://docs.parallel.ai/getting-started/rate-limits.md):
  - Search: 600 per minute
  - Extract: 600 per minute
  - Tasks/TaskGroups: 2,000 per minute
  - FindAll: "300 per hour"
  - Entity Search: 600 per minute
  - Monitor: 300 per minute
  - "Rate limits apply to POST requests that create new resources."
  - A 429 is returned when limits are exceeded.
- **Scale plan limits.** Search and Extract rise to "1,500/min (Excluding Turbo)" (https://parallel.ai/pricing.md).

## 4. Webhooks
Source: https://docs.parallel.ai/resources/webhook-setup.md

- **Standard.** "Our webhooks follow standard webhook conventions" (Standard Webhooks / Svix).
- **Headers.** `webhook-id`, `webhook-timestamp`, and `webhook-signature` (`v1,<base64>`, space-delimited when multiple).
- **Signing.**
  - "signed using HMAC-SHA256 with **standard Base64 (RFC 4648) encoding with padding**" over `<webhook-id>.<webhook-timestamp>.<payload>`.
  - The secret has the `whsec_` prefix stripped and is then Base64-decoded.
  - There is one account-level secret, under "**Settings → Webhooks**".
- **Retries.** "Initial delay: 5 seconds", "Exponential backoff (doubles per failed request)", "Multiple attempts over 48 hours". "Any other status code [than 2xx] will trigger retries."
- **Duplicates.** "duplicate events may be sent… detect and safely ignore duplicate events using the `webhook-id` header."
- **Event types.**
  - Task: `task_run.status` only (completion or failure). The payload `data` is the Task Run object without the output, so you fetch the result separately (https://docs.parallel.ai/task-api/webhooks.md).
  - FindAll: see section 1.
  - Monitor: see section 1.
- **Not documented.** A timestamp tolerance window and the exact number of retry attempts were not found in official pages.

## 5. Terms / legal / security

### Commercial use and ownership
- https://docs.parallel.ai/resources/faqs.md: "Subject to our Terms of Service - you own the output you create with Parallel, including the right to reprint, sell, and merchandise."
- Customer Terms §4(b) (https://parallel.ai/customer-terms.md): "Customer retains all right, title and interest in and to the Customer IP" (inputs and outputs).

### Showing results to end users
Allowed, with restrictions. Customer Terms §2(b) (https://parallel.ai/customer-terms.md) gives Parallel's license "includes the right for Customer to use the Parallel API to integrate the Services into the Customer Applications and to make Customer Applications available to End Customers", provided that:
- "(i) Customer Output generated from one query shall be primarily for the use of one End Customer only, and shall not be copied, cached, stored, or made available to other End Customers or other third parties"
- "(ii) Customer shall not copy, cache, or store any significant portion of any Customer Output to create the AI and Data Selling Services"

Related clauses:
- **End Customer terms.** End Customers must have "agreed to be bound by terms and conditions at least as protective of the Parallel IP as those hereunder" (§1(f)).
- **Prohibited uses** (§2(c)(vi)): using outputs to "create synthetic training data to develop or train a language model", or to "create databases, data brokerage, data selling/reselling businesses". §2(c)(xi) bars "making available Customer Outputs from previous queries for future uses".
- **No reselling** (§2(c)(iv)): no "sell, resell, … distribute, publish… Customer Outputs (except as expressly permitted under Section 2(b))".
- **Integration impact.** The terms restrict caching or sharing one query's output across users, or building a shared database from outputs.

### High-risk uses / FCRA
- Customer Terms §8(e): "Customer shall not use the Services and/or the Customer Outputs to make automated decisions without human oversight that have a significant adverse impact on individual rights in high-risk areas such as employment, healthcare, finance, legal, housing, insurance or social benefits."
- The words "FCRA" and "consumer report" appear nowhere in the Customer Terms, ToS, or Privacy Policy. **FCRA-specific language: Not found in official pages.**
- Outputs are "not tested, verified, endorsed or guaranteed to be accurate" (§5(b)).

### Data use and training
- Customer Terms §4(b) grants Parallel a "perpetual, sublicensable license" to Customer IP for performing the service, improving it, and creating aggregated de-identified data: "Parallel may use Customer IP to train and improve the machine learning and other artificial intelligence models used to provide the Services. Customer IP used for training is not linked to any individual during training."
- FAQ: "Enterprise plans with zero data retention exclude that use. Search API traffic sent to the EU endpoint is also excluded."

### Personal data
- Customer Terms §4(d): "Before Customer use the Services to process any 'personal data'… Customer shall separately execute Parallel's Data Processing Addendum".
- A DPA document is not published on the sites. Pricing lists "Custom MSA and DPA" for Enterprise.

### Data retention
- **Standard plan.** The retention period for API inputs and outputs is **Not found in official pages**.
- **Task Groups.** "Task Group runs are subject to your account's data-retention configuration. Persist any results your application needs" (https://docs.parallel.ai/task-api/group-api.md).
- **ZDR definition.** "A deployment mode in which Parallel does not retain request or response data after a run completes" (https://docs.parallel.ai/getting-started/glossary.md).
- **ZDR by plan** (https://parallel.ai/pricing.md):
  - Not on Build.
  - Scale: "Zero data retention is included on Scale as Hybrid ZDR. It turns on once a signed agreement is in place. Once active, synchronous APIs retain no content and asynchronous APIs retain it for up to 8 days."
  - Enterprise: "Custom data retention".
- **ZDR limitations.** Stateful features such as Responses follow-ups and Interactions are unavailable under ZDR (glossary).
- **EU endpoint.** It "doesn't retain the request or response content" (https://docs.parallel.ai/resources/eu-data-residency.md).

### Storage location and security
- FAQ: "All data is encrypted in transit (TLS 1.2+) and at rest in US-based data centers."
- FAQ: "Parallel is SOC-II Type 1 and Type II certified as of April 2025". The report is available via partnerships@parallel.ai and the Trust Center.
- Pricing page lists "SOC 2 Type 2", "HIPAA-ready offering" (BAA on Enterprise), "GDPR Compliance", and SSO/SAML (Enterprise). trust.parallel.ai was not fetched because it is outside the allowed hosts.

### Privacy Policy and Terms of Service
- **Privacy Policy** (https://parallel.ai/privacy-policy.md) covers "www.parallel.ai (the 'Sites')". It retains personal data "for as long as necessary". For international transfers it relies on "Standard Contractual Clauses".
- **Website ToS** (https://parallel.ai/terms-of-service.md) governs the websites. API use is under the Customer Terms.
- **Governing law** is California, with courts in San Francisco (Customer Terms §11(f)).
- **SLA.** Self-serve gets "commercially reasonable efforts" availability (§3(a)). The uptime SLA is Enterprise only (pricing page).

## 6. International coverage, languages, citation format

### Geo-targeting
- Search `advanced_settings.location` takes an "ISO 3166-1 alpha-2 country code". The supported list covers 37 countries, including us, gb, de, fr, jp, in, br, cn, and kr (https://docs.parallel.ai/search/advanced-search-settings.md).

### Languages
- "Turbo currently supports English and Japanese-language queries. For broader multilingual coverage, use `basic` or `advanced`." (https://docs.parallel.ai/search/modes.md)
- An official list of supported languages for Task, FindAll, or Monitor was not found in official pages.

### Data residency
- US by default: "Parallel routes traffic to the US by default" (EU residency page).
- The EU endpoint covers Search (basic mode only, up to 20 results, no live fetch) and Extract (up to 20 URLs). It requires an enterprise agreement.

### Public web only
- "we only access what can be reached on the public web without authentication" (FAQ).

### Citation formats
- **Task API and Monitor.** `basis[]` holds `{field, citations:[{url, excerpts[]}], reasoning, confidence}` (https://docs.parallel.ai/task-api/guides/access-research-basis.md). Monitor event outputs include `basis` (monitor events page).
- **FindAll.** Uses `basis` with reasoning and citations (findall quickstart).
- **Responses API.** Uses "OpenAI-style `url_citation` annotations", each carrying "the source `url` and `title`, plus `start_index`/`end_index`" (https://docs.parallel.ai/responses-api/features/citations.md).
- **Search and Extract.** Return URLs with excerpts or markdown (quickstarts).
