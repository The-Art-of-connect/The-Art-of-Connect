## 1. Products / APIs

### General

- Product chooser: "Use the [Agent API] for asynchronous, multi-step research, list building, and structured enrichment." / "Use [Monitors] to run recurring searches and receive newly discovered results." (D:admin/faqs.md)

### 1.1 Websets API (async)
Source: D:websets/quickstart.md unless noted.
- What it is: "Websets is a list-building and data enrichment API for companies, people, and other entities on the web."
- Query + criteria + enrichments: "A Webset starts with a natural-language query and a target item count. Add criteria that every result must satisfy and enrichment fields to populate for each accepted item."
- Async delivery: "Results arrive asynchronously through the dashboard, API, or webhooks." / "Receive results: Poll for status, use webhooks for updates, or check the dashboard as items arrive."
- Verification: "Websets finds candidates and checks each one against your criteria. Only matching results become items."
- Enrichments: "For each verified item, Websets searches for the additional data you requested, such as a CEO name, funding amount, or contact information."
- Count is a target: "`count` is a target, not a guarantee." … "the final item count can be lower than requested."
- Latency: "Small websets finish in minutes; requests for 1,000+ items scan a much larger candidate pool and take significantly longer."
- Item limit: "The legacy Free plan caps a webset at 25 verified results." No maximum `count` is documented in the API schema (`count`: "minimum: 1", default 10) — D:websets/api/websets/create-a-webset.md. Hard max per webset: Not found in official pages.
- SDK polling helper: `exa.websets.wait_until_idle(webset.id)` / `waitUntilIdle(..., {timeout: 60000, pollInterval: 2000})`.
- Endpoint: `POST https://api.exa.ai/websets/v0/websets/` (cURL example in quickstart).
- Large/exhaustive lists: "For large or exhaustive lists, use [Agent Ultra]… accepts a `budget` (`maxCostDollars`, `maxDurationSeconds`)".

Create-a-webset schema (D:websets/api/websets/create-a-webset.md):
- Creation starts processing: "The Webset will automatically begin processing once created." `externalId` supported ("Webset with this externalId already exists" = conflict).
- `search.query`: "maxLength: 5000"; "Any URLs provided will be crawled and used as additional context for the search."
- Criteria count: `criteria` "Criteria every Item is evaluated against. Generated from the query when omitted." "minItems: 1", "maxItems: 5"; each criterion description "maxLength: 1000".
- Entity types: `Entity` oneOf `CompanyEntity`, `PersonEntity`, `ArticleEntity`, `ResearchPaperEntity`, `CustomEntity`; "Entity the Webset returns results for. Detected from the query when omitted."
- People cap: `maxPeoplePerCompany` "Optional soft cap for people searches."
- `recall`: "Whether to estimate how many relevant results exist for this search."
- `exclude` / `scope` (sources `import` | `webset`); scope relationship `limit` "minimum: 1, maximum: 10".
- Enrichment `description` "maxLength: 5000"; `format` enum: `text, date, number, options, email, phone, url`; `options` "minItems: 1, maxItems: 150".
- Preview: "Returns how a search query will be interpreted before you create a Webset, including the detected entity and generated criteria." (D:websets/api/websets/preview-a-webset.md)
- Additional searches: "The default behavior is to reuse the previous Search results and evaluate them against the new criteria." (D:websets/api/websets/searches/create-a-search.md)

Item / verification output (D:websets/api/websets/items/get-an-item.md):
- `WebsetItemEvaluation`: `criterion`, `reasoning` ("The reasoning for the result of the evaluation"), `satisfied` enum `'yes' | 'no' | unclear`, `references` [{`title`, `snippet`, `url`}] ("The references used to generate the result.").
- `EnrichmentResult`: `status`, `format`, `result`, `reasoning`, `references`, `enrichmentId`.

Imports (D:websets/api/imports/create-an-import.md, D:websets/imports-and-search.md):
- "Creates an Import for your own data. Upload the file to the returned `uploadUrl` before `uploadValidUntil`, 1 hour after creation. Use an Import to enrich its records, to search within them with `scope`, or to leave them out of searches with `exclude`."
- Format `csv` only; "The size of the file in bytes. Maximum size is 50 MB." (`maximum: 50000000`).
- Guide: "When you already have a list of URLs (companies, people, products, etc.), you can **import** them into a Webset."

Websets monitors (D:websets/api/monitors/create-a-monitor.md):
- "creates a Monitor that searches for new Items for a Webset on a `cron` schedule in the given `timezone`."
- "The schedule must trigger at most once per day." Monitor search `criteria` "maxItems: 5"; `behavior` default `append`.

Rate limits: "`/websets/*` | 20 QPS | 20 QPS | 20 QPS"; "Websets searches also have plan-based concurrency limits, which you can check with [Get Team Info]." (D:admin/billing.md). Team info returns `maxConcurrent` / `maxQueued` (D:websets/api/teams/get-team-info.md).

### 1.2 Search API (sync)
Source: D:search/quickstart.md
- "Exa Search is a web search API that takes a natural language query and returns ranked web results with clean page content."
- Results: "Search returns up to 10 results by default. Set `numResults` to request up to 100 results… Search does not support pagination." Enterprise: "Up to 1,000 results per search" (D:admin/pricing.md).
- Latency table: `auto` "~1 second"; `lite` "~200 ms"; `deep-lite` "~4 seconds"; `deep` "4–15 seconds"; `deep-reasoning` "12–40 seconds" (D:admin/pricing.md).
- Categories: `company, publication, news, personal site, financial report, people`; "`people` and `company` return higher-quality people profiles and company pages." (D:reference/search.md)
- `userLocation`: "Pass a two-letter ISO 3166-1 country code such as "US"".

### 1.3 Contents API (sync)
- "Exa Contents is a content extraction API that returns clean page content from URLs, handling JavaScript-rendered pages, PDFs, and complex layouts automatically." (D:contents/quickstart.md)
- "Check `statuses` for the success or failure of every URL." Freshness via `maxAgeHours` + `livecrawlTimeout`.
- Rate limit "`/contents` | 100 QPS" (D:admin/billing.md).

### 1.4 Answer API (sync, optional streaming)
- "`/answer` performs an Exa search and uses an LLM to generate either: 1. A direct answer… 2. A detailed summary with citations" (D:reference/answer.md)
- "The endpoint also supports streaming (as `stream: true`)"; supports `outputSchema`; OpenAI-compatible chat-completions interface.

### 1.5 Research API — REMOVED
- "Requests to the retired Research API (`/research/*`) return HTTP 410. Use [Deep Search] or [Exa Agent] for long-running research." (D:reference/deprecations.md)

### 1.6 Exa Agent API (async; replacement for Research)
Source: D:agent/quickstart.md
- "Exa Agent is an async, usage-based web research agent API for high-compute tasks like list building, enrichment, and deep research."
- "Exa Agent is higher-latency and async by design."
- Delivery: SSE ("Add `Accept: text/event-stream` when creating a run to receive server-sent events") or polling ("save the returned `id` and poll the run until it reaches a terminal status"). No webhooks for Agent runs found in official pages.
- Citations: "`output.grounding`: citations for text or structured fields".
- Contact info: "To request contact information, describe the desired contact fields in `outputSchema`… `{ "type": "string", "format": "email" }`… `"format": "phone"`".
- Budget: "`budget.maxCostDollars` accepts `$1` to `$100` for every effort."
- Concurrency: "50 Agent runs can be in progress at a time." (D:admin/billing.md)

### 1.7 Monitors API (scheduled, webhook delivery)
Source: D:monitors/quickstart.md
- "Each monitor runs Exa searches on a recurring schedule and delivers results to a webhook endpoint."
- "The minimum interval is one hour." "each run may be delayed by up to 30 minutes".

Websets detail (D:websets/pricing.md):
- "Websets offers usage-based pricing with no required monthly subscription. You pay for the compute and searches used to build your dataset. Usage draws from your team's Exa credit balance".
- "There is no fixed price per match." Example: "3 ACUs and 250 searches" = "\$1.55"; "If that search returned 50 verified matches, its average cost would be \$0.031 per match."
- Example per-match costs: \$0.001 (Vanguard investment professionals), \$0.006, \$0.012, \$0.044 (narrow).
- "A search that finds few or no matches is still billed for the compute and searches it used".
- "Enrichment columns use the same \$0.10 per ACU and \$5 per 1,000 searches." "Contact enrichment adds \$0.02 per email found or \$0.07 per phone number found".
- Legacy: "Legacy Starter and Pro plans charge 10 Websets credits for each match. On the Pro plan, that is \$0.045 per match… On the Starter plan, it is \$0.061 per match." "Switching to usage-based pricing cannot be undone."

Plans / free credits / minimums:

## 3. Authentication, base URLs, rate limits
- "Send the key in the `x-api-key` header. `Authorization: Bearer <EXA_API_KEY>` also works." (https://exa.ai/auth.md)
- Hosts: "`https://api.exa.ai`: the Exa API"; "`https://mcp.exa.ai/mcp`: the hosted MCP server" (https://exa.ai/auth.md). Websets base: `https://api.exa.ai/websets/v0/...` (D:websets/quickstart.md). EU: "api.eu.exa.ai" — "An EU team's API key works only on the EU endpoint" (https://exa.ai/eu-data-residency; Enterprise only per pricing page).
- Rate limits (D:admin/billing.md): "10 QPS on the Starter plan (free), 25 QPS on the Developer plan (pay-as-you-go), and 50 QPS on the Growth plan"; deep search 5/12/25 QPS; `/contents` 100 QPS; `/agent/runs` 5/12/25 QPS "and 50 active runs"; "`/websets/*` | 20 QPS"; "Rate limits … apply to your team as a whole, across all of its API keys." Exceeded: "`429 Too Many Requests`. Wait for the `Retry-After` header when present".
- Developer auto-upgrade: "Add \$1,000 in credits within any 30-day window and your team's rate limit rises to **50 QPS for 90 days**".
- Per-key rate limit cap: "Rate limit cannot exceed team's limit of 500 QPS" (D:reference/team-management/create-api-key.md).
- Geo blocks: "Exa blocks API access from sanctioned or otherwise restricted countries and regions, including Crimea, Cuba, Iran, North Korea, Russia, Syria, Ukraine, and Venezuela." (D:admin/security/overview.md)

## 4. Webhooks
Websets webhooks:
- Creation: "Creates a Webhook that delivers the selected events to your URL as they occur. The response includes the signing `secret` used to verify deliveries; it is only returned on creation." (D:websets/api/webhooks/create-a-webhook.md)
- Redirects: "**Redirects are not followed.** … If your endpoint responds with a 3xx redirect, the delivery will be treated as a failure."
- Event types (D:websets/api/events/types.md): `webset.created`, `webset.deleted`, `webset.paused`, `webset.idle`, `webset.search.created`, `webset.search.updated`, `webset.search.completed`, `webset.search.canceled`, `webset.item.created`, `webset.item.enriched`, `import.created`, `import.completed`, `webset.export.created`, `webset.export.completed`, `monitor.created`, `monitor.updated`, `monitor.deleted`, `monitor.run.created`, `monitor.run.completed`. Payload: "A unique `id`", "The event `type`", "A `data` object containing the full resource", "A `createdAt` timestamp". "Events are retained for 60 days before being automatically deleted."
- Signature (D:websets/api/webhooks/verifying-signatures.md): "Exa uses HMAC SHA256 to sign webhook payloads. The signature is included in the `Exa-Signature` header" — format `t=<timestamp>,v1=<hex>`; "concatenating the timestamp, a period, and the raw request body"; recommends "rejecting webhooks with timestamps that are too old (e.g., older than 5 minutes)" and timing-safe comparison.
- Retries: an attempts log exists — "List all attempts made by a Webhook ordered in descending order." with fields `attempt` ("The attempt number of the webhook"), `successful`, `responseStatusCode`, `attemptedAt` (D:websets/api/webhooks/attempts/list-webhook-attempts.md); signature page links "Set up [webhook retries and monitoring]". Retry count/backoff schedule and success criteria: Not found in official pages.
- Pull alternative: events list endpoint (D:websets/api/events/list-all-events.md).

Monitors API webhooks (D:monitors/quickstart.md): same `Exa-Signature` scheme ("Every delivery includes an `Exa-Signature` header in the form `t=<timestamp>,v1=<signature>`"); "Store `webhookSecret` when you create the monitor. It is returned only once"; "Optional monitor `metadata` is echoed in webhook deliveries"; "Your webhook must use HTTPS".

Agent API: SSE streaming + polling only; webhooks Not found in official pages.

## 6. Coverage, people data, citations
- International: People library "300M+ people profiles", "190+ countries" (https://exa.ai/library/person). Websets: "1B+ people, 70M+ companies, 211M+ places, and 1.2B+ products" (https://exa.ai/products/websets). Pricing page: "Search over 1B+ people across the web". Websets product page shows examples in Berlin/Paris/London/Stockholm/Toronto. Search supports `userLocation` ISO country codes. Per-country coverage figures: Not found in official pages.
- People fields returned (public professional info):
  - People library: "Current title and location, current and past roles, employers, education, publications and recent activity such as professional posts and news mentions." (https://exa.ai/library/person)
  - Websets Person item: `url` ("The URL of the person profile"), `person.name`, `location`, `position` ("The current work position"), company, `pictureUrl` ("The image URL of the person"), work history (title, location, date range, company with `linkedinUrl`), education history (D:websets/api/websets/items/get-an-item.md).
  - Search person entity: name, firstName, lastName, location, workHistory, educationHistory, research metrics (h-index, citation counts, notable works) (D:reference/search.md).
- Contact details: NOT included in base person records; available as paid enrichment — Websets enrichment `format` `email`/`phone` and "Contact enrichment adds \$0.02 per email found or \$0.07 per phone number found" (D:websets/pricing.md); Agent "An Agent lookup that returns an email address or phone number for a person or company. Billed per contact found" (D:admin/pricing.md). Recruiting page lists "Contact data" (https://exa.ai/use-cases/recruiting).
- Citation formats:
  - Websets: per-criterion `references` [{title, snippet, url}] + `reasoning` + `satisfied` yes/no/unclear; per-enrichment `references` (D:websets/api/websets/items/get-an-item.md).
  - Search results: `title, url, publishedDate, author, id, image, favicon, text, highlights, summary, subpages, entities, extras`; synthesized output has `grounding` [{field, citations[{url,title}], confidence low|medium|high}] (D:reference/search.md).
  - Agent: `output.grounding`; Answer: `citations` (D:agent/quickstart.md, D:reference/answer.md).
  - FAQ: "the application and its language model remain responsible for how retrieved information is interpreted and presented." (D:admin/faqs.md)
- Crawler: "It respects the Robots Exclusion Protocol… and does not attempt to bypass logins, paywalls, or CAPTCHAs." (D:admin/faqs.md)
